# 搭搭动 Dabble — 运动搭子工具 产品设计文档

> 日期：2026-05-09
> 状态：已确认（搭子核心 / 简化版）

## 1. 产品定位

**目标用户**：大学生
**核心问题**：一个人动不起来。运动健身缺乏持续动力，难以坚持锻炼计划。
**解决方案**：让用户**看见熟人正在动**，从而跟着一起动。一句话——「跟你的运动搭子一起运动」。

**MVP 社交模式**：仅熟人模式，不做陌生社交
**产品形态**：Web 应用（移动端优先响应式）
**视觉风格**：轻松可爱风（小红书 / NesCoffee 调性），但避免花里胡哨的动画/特效

### 1.1 产品哲学

> 我们不需要更精确的数据、更花哨的图表、更多种类的训练计划。
> 我们需要的是：在你想偷懒的那一刻，看见一个具体的熟人正在动，然后想起来「Ta 都动了，那我也动一下吧」。

所有功能都为了制造那一刻而存在。其他东西能砍就砍。

### 1.2 冷启动路径（依靠性格测试病毒分享）

平台没有用户也能拉到第一批用户，靠的是**运动性格测试卡片**：

1. 新用户完成 6 道性格测试题
2. 结果页生成「运动性格卡片」（含性格名、emoji、标语、渐变配色）
3. 用户分享卡片到微信/朋友圈，附文案「你是哪种运动性格？」
4. 好友点开链接 → 完成自己的测试 → 系统提示「Ta 邀请你一起记录运动」→ 自动加为好友
5. 双方在平台上互见运动状态，搭子关系自然形成

**重点**：性格测试只是**拉新钩子**，不是核心玩法。注册之后性格就降级为静态身份标签。

## 2. 行为驱动模型

只保留两个引擎，砍掉所有需要花哨视觉支撑的部分：

### 引擎一：社会触发（搭子效应）— **核心驱动**
- 首页置顶「正在运动的搭子」
- 「此刻有 N 位搭子正在运动，要一起？」
- 好友开始运动 → 推送「XX 刚开始运动了」
- 云陪体验：双方同一时间窗口运动，实时感知彼此状态
- Feed 流持续可见好友运动动态

### 引擎二：损失厌恶（周活跃，正向版）
- GitHub 风格运动热力图
- **周活跃连续**：以「周」为单位计算，不是日打卡（避免一天偷懒就崩盘）
- 文案永远正向：「再运动 N 次就能完成本周目标」
- 搭子提示：「你的搭子本周已运动 X 次，超过你了」

### 砍掉的引擎（明确不做）
- ❌ 徽章/勋章系统
- ❌ 性格能量状态（活力/枯萎之类）
- ❌ 性格进化动画
- ❌ 任何粒子特效、闪光、庆祝爆炸动画

如果以后必要，再加一两个轻量元素回来。MVP 不做。

## 3. 信息架构

**3 个核心页面**，每页只做一件事：

### 3.1 首页（核心触发器）

精简后只有 3 段，目的就是把人推到「记录运动」按钮：

1. **搭子状态卡**（首要触发器）
   - 当前正在运动的好友 → 显示头像 + 「XX 正在运动中」
   - 当前有约定中的搭子会话 → 显示倒计时
   - 无搭子时 → 引导分享性格卡片或添加好友

2. **本周进度**
   - 「本周已运动 X / Y 次」
   - 进度条
   - 正向文案：「再运动 N 次就能完成本周目标！」或「本周目标已达成 🎉」

3. **记录运动按钮**
   - 全宽紫色渐变大按钮
   - 简短提示文案

**身份信息**（性格 + 名字）放在顶部 header，做成一个小标签即可——不是卡片，不是 CTA，不占视觉重心。

### 3.2 运动圈（社交 Feed）

- Feed 动态流，仅显示好友
- 动态类型：
  - 好友运动打卡
  - 搭子共同运动
- 互动：点赞、评论、**「见证」**（替代普通点赞，更有仪式感）

### 3.3 我的（个人页）

- 顶部：性格身份卡（emoji + 名字 + 标语，纯静态展示）
- 年度运动热力图
- 运动历史记录
- 搭子历史（一起运动过的人）
- 性格测试重做入口
- 账号设置

**没有徽章墙**。

## 4. 运动搭子系统（产品核心）

搭子系统是搭搭动 Dabble 的核心价值，区别于 Keep / 咕咚等工具型 App。所有其他模块都为这个系统服务。

### 4.1 时间窗口模型（软时间窗口 ±30 分钟）

搭子**不要求同地点运动**，只要求在约定时间段内运动，即为「云陪」。

**软时间窗口规则：**
- 好友之间约定一个时间段（如「今晚 20:00–21:00 一起动」）
- 系统在窗口前 30 分钟开始提醒
- 窗口期内任意一人开始运动，其他人收到「XX 已经开始了」通知
- 第一个开始的人会看到「等待搭子加入」状态
- 所有人都记录过运动 → 会话自动成功，生成「搭子运动记录」

**为什么用软时间窗口：**
- 大学生宿舍楼不同、运动偏好不同，强制同地不现实
- 「同时段」足以制造「有人陪我」的心理在场感

### 4.2 云陪三阶段体验

**阶段一：约前 30 分钟（仪式准备）**
- 推送提醒：「你与 XX 约好的运动时间快到了」
- 首页搭子卡变为「即将开始」+ 倒计时
- 可发送预设回应（「准备好了！」「稍等一下」）

**阶段二：窗口期内（同在感）**
- 任意一方开始运动 → 其他人首页弹出「XX 正在运动中 🔥」横幅
- 实时状态同步（加入 / 还没开始 / 已完成）
- 可发送加油表情

**阶段三：会话结束（轻量庆祝）**
- 都完成 → 生成「搭子运动记录」发到 Feed（**仅一条简单 Feed 项，不做爆炸特效**）
- 一方未完成 → 另一方收到「下次一起加油」（不批评未完成方）

### 4.3 弱关系激活（V2）

会话结束后系统留存搭子记录。一段时间后对方重新活跃 → 推送：「之前和你一起运动的 XX 又开始运动了，要约一次吗？」

历史搭子列表可在「我的」页面查看。

## 5. 运动性格系统（**仅冷启动**）

> 重要：性格只是拉新钩子。注册之后它就是个静态身份标签，不是日常玩法。

### 5.1 性格分类维度

基于 4 个量化的运动行为维度交叉生成：

| 维度 | 数据源 | 光谱 |
|------|--------|------|
| 时间偏好 | 运动记录时间分布 | 晨型 ↔ 夜型 |
| 强度偏好 | 类型 + 时长 | 高强度 ↔ 低强度 |
| 频率模式 | 每周天数方差 | 稳定 ↔ 爆发 |
| 多样性 | 类型种类 | 单一 ↔ 多样 |

### 5.2 八种运动性格

| 性格 | 维度特征 | 标语 |
|------|----------|------|
| 🌅 黎明行者 | 晨型 · 稳定 · 中高强度 | 太阳还没醒，我已经在路上了 |
| 🦉 夜猫铁人 | 夜型 · 高强度 · 爆发 | 夜深了，铁馆才是我的主场 |
| 🔥 燃脂战士 | 高强度 · 稳定 · 专精 | 不流汗不痛快 |
| 🧘 禅意行者 | 低强度 · 稳定 · 多样 | 运动是和自己对话 |
| 🌊 自由浪人 | 爆发 · 多样 · 随性 | 想动就动，不想就躺着 |
| 🎯 精准猎手 | 规律 · 专精 · 计划型 | 每一练都在计划之中 |
| 🦋 全能蝶变 | 多样 · 均衡 · 全能 | 什么都会一点，什么都爱 |
| 🏔️ 马拉松之魂 | 耐力 · 长时 · 坚韧 | 不在于快，在于不停 |

### 5.3 性格生成与展示

**冷启动（新用户）：**
- 6 道趣味情景选择题（如「期末考试周你会...」）
- 3 分钟完成
- 生成性格卡片（含 emoji、名字、标语、渐变背景）
- 立即可分享（病毒入口）

**注册后：**
- 性格作为静态身份标签
- 仅在「我的」页面顶部展示
- 首页 header 中显示一个小 chip
- **不变化、不进化、不带能量**

> 用户首次完成测试后想重测，可在「我的」页面手动重做。系统**不会**自动重算。

### 5.4 明确不做的事

- ❌ 能量值（0–100%）
- ❌ 状态条（活力/渴望/枯萎/进化）
- ❌ 14 天滑动窗口重算性格
- ❌ 性格进化动画
- ❌ 颜色随活跃度变化
- ❌ 任何「Tamagotchi 式」情感投资机制

## 6. 社交功能

### 6.1 好友系统（V1）
- 通过性格卡片分享链接添加好友
- 通过邮箱/用户名搜索添加好友
- 好友接受后双方互见运动动态

### 6.2 运动圈 Feed（V1）
- 仅好友动态（无陌生人）
- 动态类型：运动打卡、搭子共同运动
- 互动方式：点赞、评论、「见证」

### 6.3 「见证」是核心社交动作
- 替代普通点赞
- 比点赞重，比评论轻
- 给对方的运动一个「我看见了」的承认

### 6.4 报告卡（V2）
- 每周日晚自动生成
- 内容：运动天数 + 总时长 + 搭子次数 + 好友排名
- 一键生成分享图

## 7. 数据录入

### V1（MVP）：手动记录
- 选择运动类型（跑步/健身/游泳/瑜伽/骑行/篮球等）
- 输入时长，距离可选
- 一键提交，低摩擦

### V2：Keep API 同步
- 对接 Keep 开放 API，自动同步运动记录

### V3：扩展数据源
- Apple Health
- 微信运动

## 8. 技术方案

### 8.1 技术栈

| 层级 | 选择 | 理由 |
|------|------|------|
| 前端 | Next.js 14+ App Router + TypeScript | 全栈一体，类型安全 |
| 样式 | Tailwind CSS | 快速实现可爱风格 |
| 数据库 | PostgreSQL（Supabase 托管） | 关系型适合社交场景 |
| ORM | Prisma | 类型安全的迁移 |
| 认证 | NextAuth.js | 邮箱/密码登录 |
| 部署 | GitHub + Vercel | 零运维 CI/CD |

> 注意：**没有 Framer Motion**，**没有 Recharts**。MVP 不需要它们。
> 热力图用纯 CSS Grid 实现即可。

### 8.2 核心数据模型

**User（用户）**
- id, name, email, passwordHash, avatar
- personalityType（一次性写入，可在「我的」手动重做）
- weeklyTarget（每周目标次数，默认 3）
- lastWorkoutAt

**Workout（运动记录）**
- id, userId
- type, duration, distance（可选）
- recordedAt
- source（manual / keep / apple_health）
- buddySessionId（关联搭子会话，可选）

**BuddySession（搭子会话）**
- id
- windowStart, windowEnd
- status（pending / active / completed / expired）
- createdAt

**BuddySessionParticipant（搭子会话参与者）**
- id, sessionId, userId
- joinedAt（null 表示未加入）
- workoutId（null 表示未完成）

**Friendship（好友关系）**
- id, userId, friendId
- status（pending / accepted）
- createdAt

**FeedItem（动态）**
- id, userId
- type（workout / buddy_workout）
- content（JSON）
- createdAt

**Interaction（互动）**
- id, feedItemId, userId
- type（like / comment / witness）
- content（评论文字，点赞/见证为 null）

> **注意：没有 Badge 表，没有 personalityEnergy 字段。**

### 8.3 核心数据流（记录运动时）

```
POST /api/workouts
  ├── 写入 Workout
  ├── 若有 buddySessionId → 更新参与者状态
  │     └── 若所有参与者都完成 → 会话标记 completed + 生成 buddy_workout Feed
  ├── 更新 lastWorkoutAt
  └── 生成 FeedItem（普通 workout 或 buddy_workout）
```

> 流程比之前简单——没有徽章解锁检查，没有能量重算，没有性格重算。

## 9. MVP 范围

### V1 MVP（先做）
- ✅ 用户注册/登录
- ✅ 运动性格测试（6 道题）+ 8 种性格 + 分享卡片（**仅冷启动用**）
- ✅ 手动记录运动
- ✅ 周活跃热力图（GitHub 风格）
- ✅ 本周进度（正向文案）
- ✅ 好友系统 + 运动圈 Feed（点赞/评论/见证）
- ✅ **搭子系统**：时间窗口约定 + 云陪状态同步 + 搭子运动记录
- ✅ 3 页结构：首页 / 运动圈 / 我的

### V2 迭代（后做）
- ⏳ Keep API 数据同步
- ⏳ 周报告卡 + 分享图
- ⏳ 搭子弱关系激活推送
- ⏳ 运动性格匹配推荐（陌生人模式探索）

### 明确不做（除非有强证据）
- ❌ 徽章 / 勋章系统
- ❌ 性格能量状态
- ❌ 性格进化机制
- ❌ 复杂动画特效
- ❌ 社交契约（公开承诺 + 见证完成）

如果未来用户数据证明需要其中某项，再单独评估。MVP 阶段不投入。
